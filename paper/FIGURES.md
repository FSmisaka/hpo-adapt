## Fig. 1 — System architecture (no data needed; draw from README diagram)

The closed loop:

```
Task ─▶ Initial Setup Agent ─▶ S0 ─▶ Classical HPO (Optuna) ─▶ TrialLogs
              ▲                                                    │
              │                                                    ▼
        Agent Memory ◀── Experience ◀── Outcome ◀── Revised Setup ◀── RL Controller
        (SQLite)          (after each step)          Agent          (Q-Learning,
                                            executes A_t          7 actions)
```

Requirements for the drawing:
- Highlight the Observe / Decide / Execute color coding:
  Diagnostic Engine = Observe (deterministic Python, no LLM in metrics);
  RL Controller = Decide; Revised Setup Agent = Execute.
- One horizontal band per closed-loop iteration
  (S_t → HPO → D_t → A_t → S_{t+1}).
- Show the Tool Validator as a gate between any Setup and the HPO runner.
- Style: clean boxes, arrows left-to-right; keep it readable at full
  column width (~3.3 in / 84 mm wide, or full text width ~5.5 in).

## Fig. 2 — Anytime performance (2 panels side by side, or 3 panels)

- Data: `anytime.csv` — columns task, method, seed, trial, best_so_far.
  Plot mean best-so-far vs. cumulative trials (raw objective space),
  one line per method, mean over the 10 seeds; add shaded ±1 std band if
  it does not clutter. Branin is a MINIMIZE task (lower = better) — label
  the y-axis accordingly.
- Methods (color order suggestion):
  static-random, static-tpe (baselines, dashed),
  adapt-random-action (grey), adapt-rule-only, adapt-rl-guided (solid).
- Panels: synthetic_mlp | branin | rf_digits.

## Fig. 3 — Cross-episode learning (2 panels: synthetic_mlp, branin)

- Data: `episodes_summary.csv` — task, method, episode, best_raw_mean/_std.
  x = episode index (0..19), y = mean best raw objective of that episode
  (over 10 seeds). Lines: adapt-rl (learns, Q-table + memory shared across
  episodes), adapt-random-action (control), static-tpe (reference, flat).
- Message: the RL controller's per-episode results improve with accumulated
  experience while the random control does not.

## Fig. 4 — Case study walkthrough (the "money figure", full width)

- Data: `case_study.json` — one synthetic_mlp adaptive episode where the
  controller repaired the truncated learning-rate interval (action is
  either EXPAND_SEARCH_SPACE or SHIFT_SEARCH_REGION on learning_rate;
  check the `action` field of each step in the JSON).
- Suggested layout (3 stacked mini-panels sharing the x-axis = trial index
  0..120):
  (a) best-so-far curve with round boundaries as vertical dashed lines and
      the round's action annotated (e.g. "SHIFT lr ->");
  (b) learning_rate search interval per round drawn as a horizontal bar
      per round (log scale), with the ground-truth optimum 0.45 as a
      vertical/horizontal marker line and the sampled lr values as dots;
  (c) reward per round.
- Message: diagnosis (importance + good-region / boundary concentration)
  detects that the good region is toward the upper edge → the interval is
  moved/expanded toward it → the next phase immediately samples the newly
  opened region and the optimum is found.
